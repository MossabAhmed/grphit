# مصنع الجرافيت — نظام إدارة مبسط لمصنع متوسط

واجهة عربية لإدارة المخزون والمشتريات والمبيعات والمصروفات والرواتب والتقارير باستخدام HTML وCSS وJavaScript فقط.

## الخصائص الحالية

- تخزين البيانات في **IndexedDB** داخل المتصفح، دون خادم أو اشتراك.
- العملة الافتراضية هي **الدينار الليبي LYD**، مع تنسيق عربي للأرقام.
- ترحيل البيانات القديمة من النسخة السابقة عند أول تشغيل.
- ربط الواردات والصادرات بالأصناف الفعلية.
- حساب متوسط التكلفة وتكلفة البضاعة المباعة والربح.
- تكلفة واردة شاملة لسعر الشراء والشحن والجمارك والتكاليف الأخرى.
- منع البيع عند عدم كفاية الرصيد.
- تقارير شهرية للإيرادات وCOGS والمصروفات والرواتب وصافي الربح.
- تسجيل الرواتب حسب الشهر.
- تصدير واستيراد نسخة احتياطية JSON.
- زر **تعديل** في جميع الجداول. تعديل العمليات المخزنية يعيد حساب الرصيد والتكلفة والتقارير، ويرفض التعديل إذا أدى إلى رصيد سالب.
- حذف الصنف المرتبط بحركات ممنوع لحماية تاريخ المخزون.
- طباعة فاتورة رسمية لكل عملية بيع أو تصدير، مع رقم مستند وتاريخ وبيانات العميل والكمية والوحدة والإجمالي والمدفوع والمتبقي.
- طباعة سند استلام للمشتريات، وسند صرف للمصروفات، وكشوف للمخزون والواردات والمبيعات والمصروفات والتقرير المالي الشهري.
- قوالب الطباعة باللغة العربية وباتجاه RTL، مقاس A4، مع بيانات المصنع والدينار الليبي ومواضع توقيع المسؤول والعميل أو المورد.
- تسجيل المدفوع للمورد والمتبقي عليه، مع تجميع ذمم العملاء والموردين في شاشة واحدة.
- أوامر إنتاج مبسطة تخصم الخامة من المخزون وتضيف المنتج النهائي وتحسب تكلفة الإنتاج، مع دعم الفاقد والملاحظات.
- إلغاء الواردات والمبيعات والمصروفات وأوامر الإنتاج بدل حذفها نهائيًا؛ العملية الملغاة تبقى في السجل ولا تدخل في المخزون أو التقارير.
- حقلا العميل والمورد مرتبطان بقائمة اقتراحات من جدول الجهات، مع توحيد المسافات ومطابقة الاسم المعروف لتجنب تقسيم الذمم بسبب اختلافات الكتابة البسيطة.
- لا يحسب النظام ضرائب أو يضيف ضريبة إلى الفواتير؛ أزيل حقل الضريبة من الإعدادات حتى لا يعطي انطباعًا بوجود معالجة ضريبية غير مطبقة.

## وحدات القياس

لا يسمح النظام بكتابة الوحدة كنص حر. لكل صنف فئة ووحدة مخزون أساسية:

- الوزن: جرام، كجم، طن.
- العدد: قطعة، صندوق، كرتونة.
- الحجم: لتر، متر مكعب.

يتم تخزين الرصيد داخليًا بالوحدة الأساسية. يمكن تعريف وحدة شراء أو بيع بديلة بمعامل خاص بالصنف، مثل:

```text
1 طن = 1000 كجم
1 كيس مسحوق = 25 كجم
```

عند إدخال 2 طن، يسجل النظام الكمية المدخلة 2 طن والكمية الأساسية 2000 كجم. وعند البيع يحول الكمية إلى الوحدة الأساسية قبل الخصم. يمنع النظام التحويل بين فئات غير متوافقة مثل طن وصندوق.

## التشغيل

افتح `index.html` في متصفح حديث، أو شغّل خادمًا محليًا:

```bash
python3 -m http.server 4173
```

ثم افتح `http://localhost:4173`.

يفضل استخدام خادم محلي لأن بعض المتصفحات تقيد IndexedDB عند فتح الملفات مباشرة عبر `file://`.

## قاعدة البيانات المجانية

يستخدم التطبيق IndexedDB، وهي قاعدة بيانات مدمجة في المتصفح ومناسبة لمصنع متوسط يعمل من جهاز أو متصفح واحد. يجب استخدام زر **تصدير نسخة احتياطية** بانتظام.

هذه النسخة لا توفر مزامنة بين عدة أجهزة أو مستخدمين. إذا احتاج المصنع ذلك مستقبلًا، يمكن نقل نفس النموذج إلى Supabase أو Firebase مع طبقة مصادقة وصلاحيات.

## السياسة المحاسبية الحالية

يستخدم التطبيق متوسط التكلفة المتحرك. عند الاستلام تضاف التكلفة الواصلة إلى قيمة المخزون. عند البيع تحسب تكلفة البضاعة المباعة وفق متوسط التكلفة وقت الحركة:

```text
الإيرادات - تكلفة البضاعة المباعة - المصروفات - الرواتب
```

هذه لوحة إدارة تشغيلية وليست بديلًا عن برنامج محاسبي قانوني أو مراجعة محاسب معتمد.
